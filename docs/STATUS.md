- 2026-10-24 G6 第 3 轮（时序排查，确认「绕开」有上限）：真机轮询 `GET /api/terminal/sessions` 记录 `attached` 变化——终端前台 1；**切页回编辑器 +10s 仍为 1**（ViewModel 保活连接，无窗口）；**HOME 后台 30s 即降到 0**，且 `logcat` 无 `disconnected`/`retry`（进程被系统冻结，客户端无法感知）；后台再 60s 仍 0（窗口长度 ≈ 后台时长）；**回前台 2s 内自动回到 1**。结论：切页与回前台恢复已覆盖，后台冻结与进程死亡造成的窗口在不做保活的前提下不可消除；进程死亡后因 Cookie 仅在内存还要重新登录，窗口达分钟级。若批准持久化登录 Cookie，可把该窗口压到「打开应用 → 秒级」，但这与 G1「Cookie 仅内存、按服务器隔离」的决定冲突，需明确决策。同时补了一个客户端钩子：`TerminalScreen` 监听 `ON_RESUME` 调 `TerminalViewModel.onForeground()`，解冻即主动重挂（保留 `previousSessionId`，会话已被释放时仍走「如实提示」），复测回前台重挂 **1.4s**（轮询本身占 1s）。证据同 `docs/evidence/g6-dual-client/xiaomi-14-pro/result.md`。

- 2026-10-24 G6 第 4 轮（**重测**，排除人工干扰）：因怀疑上一轮结果受「手动关过一个终端」影响，改用**带对照组**的实验重做——① 对照：`attached=1` 的 Android 会话 + `attached=0` 的脚本会话同时存在 → 浏览器挂载工作台只 `DELETE` 了 attached=0 的那个，`attached=1` 的 Android 会话**保留**；② 隔离变量：`force-stop` Android 使其降为 `attached=0` 后重新挂载工作台 → `DELETE` 直接删掉 Android 的 PTY（`sessions: []`）。结论与首测完全一致（Web 挂载工作台删除所有 `attached=0` 且不在其持久化标签里的会话，不区分 owner/项目），**不是人工关闭造成的假象**。同时重测 Android 侧三项：双端共享输出（`attached` 1→2、脚本 `echo G6_RERUN` Android 可见）、对端 DELETE 后 11s 内如实提示且不静默重建、ownerConflict 立即停手不重试、释放后恢复正常。证据同 `docs/evidence/g6-dual-client/xiaomi-14-pro/result.md`；**G6 维持未通过**，等待范围决策（A 接受限制 / B 本地 scrollback 回放 / C 持久化 Cookie）。

- 2026-10-24 G6 第 5 轮（缓解方案 B+C 落地，按用户决定）：① **C 持久化登录 Cookie**——新增 `core/persistence/CookieStore` + `PersistentCookieJar`（按 server origin 隔离，保留 HttpOnly/Secure/过期时间；退出登录清空；`DenovaClient` 可注入），真机验证 `force-stop` 重启后**直接进入编辑器**（`status ok authenticated=true`），不再需要重新登录，把进程死亡后的分钟级窗口压到秒级；② **B 本地历史快照**——`TerminalHistory`（回滚+主屏→纯文本，64KB 上限按整行从最旧处截断）与 `TerminalHistoryStore`（按 origin+项目落盘），在 `giveUp`/`exit` 时抓取，错误行新增「查看历史」只读对话框；真机验证会话被对端 DELETE 后能打开本地快照（落盘 1410B，尾部含 `# echo B_SNAPSHOT_OK` 与输出）。新增 10 个测试（历史截断/CJK 不截断、Cookie 重启复用/过期/隔离/清空/HttpOnly），本地 **196 测试 + Lint + Debug 全绿**。**性质说明**：B+C 只降低损失，不改变「Web 挂载工作台回收 `attached=0` 会话」的基线行为，G6 仍不满足原判据，收口需一条范围决定。证据：`docs/evidence/g6-dual-client/xiaomi-14-pro/result.md`。
