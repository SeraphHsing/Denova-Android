# NAV-006 抽屉搜索、选中与返回（真机）

- **日期**：2026-10-30
- **设备**：小米 14 Pro（`135babde`），Android 16
- **应用**：`com.denova.novara` Debug（本轮构建）
- **服务器**：`http://192.168.2.102:18081`（后端 0.6.3-b）
- **Web 对照**：`docs/evidence/web-baseline/2026-10-30/command-panel-390.png`（「命令」按钮打开命令面板：搜索命令 + 分组动作 + 快捷键标注）

## 本轮修复的两个真机缺陷

1. **键盘盖住结果**：搜索框原本在列表中部（y≈1570px），输入后键盘占据下半屏，结果行整块被遮住且无法点击（真机截图确认）。
   - 修复：把「导航 / 排序 / 搜索框」固定在标题栏下方；搜索态隐藏书籍区与引导卡；抽屉根布局按 IME insets 收缩（`imePadding()`）。
2. **清空搜索后列表停在中间**：搜索时列表项骤减，LazyColumn 保留旧滚动位置，清空后看起来像「书籍区与创作组消失」。
   - 修复：`LaunchedEffect(query) { listState.scrollToItem(0) }`。

另外：选中结果时先 `clearFocus()`（收键盘）并清空搜索词，再导航——对齐「命令面板选中即关闭」的语义。

## 判据与实测

| 步骤 | 结果 | 证据 |
|---|---|---|
| 输入过滤（大小写不敏感） | 通过 | 输入 `Sk` 后只剩「工具 → Skills」；`screencap` 与 uiautomator 节点一致，结果行 bounds `[203,934][1147,1002]` 位于键盘上方可点 |
| 无匹配提示 | 通过 | 输入不存在的词（如 `Skphp -v`）显示「没有匹配的动作」 |
| 选中结果跳到目标 | 通过 | 点 Skills 行 → 抽屉关闭、进入 Skills 页（节点：`☰ / Skills / 10 个 Skill / ⟳`） |
| 选中后搜索态复位 | 通过 | 再次打开抽屉：搜索框为空、键盘未弹出、列表回到顶部（书籍区与「创作 / 工具」分组完整显示，Skills 带「当前」） |
| 结果目标与高亮对应 | 通过 | 进入 Skills 后抽屉该行显示「当前」，顶栏标题为 Skills |

## 与基线的差异（已登记）

- 基线的「命令」是命令面板：搜索对象是**动作**（保存当前章节 / 打开创作 Agent / 打开版本管理 / 打开全局搜索 / 继续写作 / 切换右侧栏，带快捷键标注）；Android 是抽屉内搜索框，搜索对象是**导航目的地**，没有动作执行语义。登记 [09 VG-003](../../android-web-parity/09-visual-gap-backlog.md)，P5 按命令面板形态对齐。
- 焦点恢复：关闭抽屉后焦点不自动回到搜索框（Web 命令面板关闭后焦点回到触发按钮）。本轮只断言「选中后焦点离开输入框、键盘收起」，未做逐点焦点断言，随 P5 视觉/交互对齐一起补。
