- **应用**：`com.denova.novara` Debug（本轮构建）

## 本轮修复（都是为了「关键动作可达」）

1. `EditorScreen` 顶栏标题加 `weight(1f) + maxLines + Ellipsis`：原先标题不参与压缩，窄屏下把「终端 / 写作 / 退出 / »」整排挤出屏幕（320dp 实测这三个动作直接消失且点不到）。
2. 窄屏（`screenWidthDp < 400`）或大字体（`fontScale >= 1.3`）时，把「终端 / 写作 / 退出」收进「⋯」溢出菜单。
3. 同一条件下，打开文件区由并排改成纵向堆叠：2.0 字体并行显示时输入框只能露出 6~7 个字符，label 还会竖排换行。
4. 模式行（源码 / 富文本 / 预览 / 撤销 / 重做）加 `horizontalScroll` 且文字 `maxLines = 1`：320dp 下「撤销 / 重做」原被挤成两字竖排。

## 未覆盖 / 留给 P5 的视觉差异

- **抽屉宽度**：当前是 M3 `ModalDrawerSheet` 默认 360dp（1023dp 档实测 385dp 因可用宽度换算），未按计划改成 `min(可用宽度 - 32dp, 384dp/512dp)`；与基线 `24rem/32rem` 的精确对应放在 P5 视觉层。
- **尺寸契约**：标题栏 56dp、导航行 52dp、写作/游戏入口 58dp、抽屉内容侧 24dp 圆角等仍未落地（现状是 Material3 默认值），已登记到 `docs/android-web-parity/09-visual-gap-backlog.md`。
- **768 / 1023 的平板横屏组合**（如 1023×600 横屏）未单独跑：本轮 1023 档是竖屏比例，横屏只跑了手机比例 914×411。
- 各档截图里出现的「冲突」提示是测试数据（多次编辑同一 `ideas.md` 导致 base revision 不一致），不属于布局问题；冲突流程本身已在 P4 收口。
