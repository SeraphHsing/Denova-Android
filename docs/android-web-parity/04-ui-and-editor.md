# 04 界面、编辑器与原生控件实施规范

## 1. 坐标与对照环境

Web 使用 CSS px / rem，Android 布局使用 dp / sp。P0 在同一设备读取 `innerWidth`、`devicePixelRatio`、visual viewport、浏览器缩放、字体缩放及原生内容区尺寸，建立等效逻辑宽度。不能拿物理截图宽度直接作为 dp，也不能无条件把 `1rem` 写死为 16dp。

基准截图关闭非必要动画，使用稳定内容，锁定语言、主题、UI 字号、正文字号、字体版本和时间等动态字段。只允许遮罩明确登记的动态区域；遮罩不能覆盖控件、正文和布局差异。

手机布局的源码断点为 `max-width: 1023px`。验收宽度为 320、390、430、768、1023，并增加 844 横屏。超过手机基线的窗口单独登记产品决定；不直接扩展成未要求的桌面产品。

## 3. 设计参数和素材

DesignTokens 覆盖背景 / surface / hover / active / border / text / muted / primary、字号 / 字重 / 行高 / 字距、间距、边框、圆角、阴影、图标和动效。颜色值从相同主题解析后的值提取，保留变量用途。

图标按 Web 实际图形、stroke、viewBox 与状态建立矢量资源，并登记来源与许可证。图片、封面和用户附件保持真实资源 ID 与比例；不能用通用占位图片充当完成证据。

字体分别处理 UI、正文、等宽文字与 CJK fallback。记录实际命中的字体和许可；同一字符串需比较换行、字重和基线。系统大字体下仍需可操作，不能通过关闭字体缩放规避。

## 4. 公共组件完成顺序

| 顺序 | 组件 | 同时完成的状态 |
|---|---|---|
| 1 | 页面根容器、顶栏、安全区 | 常态、键盘、横屏、长标题 |
| 2 | 按钮、图标按钮、输入、选择、开关 | 正常、禁用、焦点、错误、提交中 |
| 3 | 抽屉、菜单、popover、对话框 | 打开、关闭、遮罩、返回、焦点恢复 |
| 4 | 列表、树、标签、分段控件 | 空、加载、分页、展开、选择、长文本 |
| 5 | Toast、错误块、确认、保存状态 | 请求 ID、局部错误、冲突、重试 |
| 6 | 消息、工具结果、审批、提问 | 流式、完整内容、历史、恢复 |
| 7 | 文件、编辑、diff、终端 | 真实内容、输入、选区、长内容 |

每个公共组件先建立状态样本和与 Web 对应的截图，再应用到页面。样本页面仅为开发验证，不加入产品导航。

## 5. 抽屉与手势

单指从左右 24 CSS px 等效边缘开始。完成横向位移至少 48px，且至少为垂直位移的 1.35 倍；垂直位移超过 8px 且占主导时放弃横向识别。输入框、可编辑文字、滑块和显式忽略区域排除。

关闭滑动仅从抽屉标题栏开始。打开一个面板时关闭其他手机面板，焦点进入抽屉返回控件；关闭后恢复到有效来源。普通正文阅读和编辑器横向内容保留自身手势。

Android 系统边缘返回与抽屉识别存在交汇，需要真机分别验证手势导航和三键导航。保持系统返回的优先权；抽屉始终有可点击入口，系统占用区域记录为平台差异，不假设所有边缘坐标均由 App 接收。

来源：[手势实现](https://github.com/SeraphHsing/denova/blob/671ef4eb609523f07d1c234cdcd242d63ce12652/web/src/components/layout/use-mobile-drawer-swipe.ts#L23)。

## 6. 安全区、键盘与滚动

使用 WindowInsets / IME Insets 计算原生可用区域，避免状态栏、导航栏和键盘重复 inset。当前输入、发送按钮、审批确认和对话框主要动作在键盘打开后仍可见。来源：[Android WindowInsets](https://developer.android.com/develop/ui/compose/system/insets)。

Web 的 visual viewport 高度检测用于浏览器；原生通过系统 Insets 实现相同可见结果。缩放、旋转和回前台不被误判成永久打开键盘。键盘关闭后恢复阅读高度及滚动锚点。

消息在用户贴近底部时跟随新增内容；用户向上阅读时保持锚点，按 Web 展示新消息提示。分页在顶部插入历史后保持原消息位置。列表详情返回恢复焦点、选中和滚动。

## 7. 原生 Markdown 编辑器

### 7.1 数据模型

唯一持久内容为 canonical Markdown。原生富文本投影、源码输入与选区都是同一文档的表示；不得分别保存两份互相漂移的正文。打开但未编辑、仅切换表示方式时，保留基线定义的原文。

本地草稿在编辑期间持续提交，内存编辑世代与已确认落盘世代分开；本地已保存状态只确认成功提交的事务，进程重建只恢复该版本。未提交输入窗口和失败表现按 [02 的持久化契约](02-architecture.md#5-状态拆分) 实现，不能依赖退出或进程清理回调补存。

内部建议分为 DocumentSession（文本、revision、编辑世代）、EditorAdapter（原生输入与命令）、MarkdownCodec（解析 / 序列化 / source map）、SaveCoordinator（保存与冲突）。只在 P1 原型证明需要时提取进一步抽象。

源码模式只按基线规范 CRLF / CR 为 LF，不把正文包装成代码围栏。切换模式时按基线清理不兼容撤销历史并重建可用选区。

来源：[MarkdownContentEditor](https://github.com/SeraphHsing/denova/blob/671ef4eb609523f07d1c234cdcd242d63ce12652/web/src/components/Editor/MarkdownContentEditor.tsx#L49)、[源码文档](https://github.com/SeraphHsing/denova/blob/671ef4eb609523f07d1c234cdcd242d63ce12652/web/src/components/Editor/markdownSourceDocument.ts#L77)。

### 7.2 选型门槛

P1 对原生编辑候选执行同一份语料测试。可使用 Compose 或 AndroidView，但必须实际覆盖段落、标题、强调、删除线、列表与嵌套、引用、代码、链接、图片、表格以及基线扩展。选库时验证许可、维护、minSdk、可扩展节点、输入和序列化行为。

候选未通过时不能将复杂块替换成纯文本预览后仍宣称完整编辑。未知 Markdown 结构需保留源片段；若无法提供 Web 中存在的编辑操作，登记该节点的缺口并继续完成原生能力或作出明确范围决定。

### 7.3 必做语料与用例

| 语料 | 必须检查 |
|---|---|
| 中英混排、emoji、组合字符 | 光标、删除、IME composing、选区偏移 |
| 多空行、尾随空白、CRLF / LF | 无修改往返、允许的规范化 |
| 嵌套列表、引用、代码围栏 | 缩进、Enter、粘贴、撤销、序列化 |
| 表格、图片、链接 | 插入、修改、删除、移动及 URL 身份 |
| 未识别的扩展节点 | 源文保留及可见能力缺口 |
| P0 冻结规模的 D03 文档与跨章节切换 | 输入延迟、峰值内存、保存世代、选区与滚动 |
| Web 与 App 并发编辑 | 无重叠合并、重叠冲突、外部版本加载 |

两类断言分开：无修改时比较原文；修改后比较 Web 的序列化输出及语义。对每个允许规范化的差异记录来源，避免用统一 trim 掩盖丢失。

G2 同时执行 [06 的 D03 性能基准](06-development-and-validation.md#4-测试数据)。数据规模、最低设备、测量方法与数值预算在 P0 冻结，原型必须附对应测量结果；仅写“长章节可编辑”不能判为通过。当前尚未实测，不在本文预填性能数值。

### 7.4 保存与引用

正文选区引用携带与 Web 对应的文件、行号范围和内容。富文本显示偏移转换到 canonical Markdown 坐标，不能拿显示字符下标直接当源文件行号。

图片上传保持服务端资源关系和返回路径。自动保存、手动保存、导航 flush、外部同步和冲突恢复统一经过同一保存协调器，详见 [03](03-api-and-state.md#8-文档保存与并发冲突)。

## 8. 消息与结构化内容

消息模型保留完整 parts，不将全部内容压成一个 String。工具调用展示输入、进度、结果和错误；JSON、diff、表格、代码、图片、审批与提问分别渲染。长内容通过懒加载、分页或展开降低渲染成本，全文仍可访问、选择或复制。

流式文字需要在不完整 Markdown 下稳定展示；对已完成部件和当前增量分别更新，避免每个 token 重建整条历史。稳定 key 关联服务端身份，不使用列表位置。

正文、游戏历史和工具详情分别建立字体、行高、可选中文本、链接和横向表格的测试。外部链接、附件和导出使用 Android 平台入口，但动作顺序、可用状态和内容结果对应 Web。

## 9. 原生终端

P1 选择或实现维护中的原生终端屏幕控件，核对许可及 VT / ANSI 能力，通过 AndroidView 接入时统一焦点和生命周期。只有完整渲染与输入用例通过后才锁定候选。

需要验证 UTF-8 跨帧、ANSI 色彩、光标定位、清屏、滚屏、宽字符、组合字符、全屏程序、粘贴、Ctrl-C、方向键、功能键、选择复制、键盘与网格 resize。普通 Text 追加日志不满足终端验收。

G5 使用 [06 的 D03 性能基准](06-development-and-validation.md#4-测试数据) 中冻结的 PTY 输出速率、回放规模和最低设备，提交渲染、输入、resize 与峰值内存的测量结果。预算未填写或没有对应结果时，不能仅凭终端画面出现就通过关卡。

输入辅助按手机 Web 实际能力核对；若触发 Android 特有系统输入界面，登记平台差异。连接、重连、重启和关闭必须呈现不同状态。

## 10. 视觉验收规则

P0 提取应用内关键元素的边界框、颜色、字号、行高、字体与位置。P1 用首屏、抽屉、编辑器、消息和对话框校准对照方法。

首轮开发采用关键边界不超过 1 个等效逻辑像素的目标；这是拟定验收阈值，P0 / P1 需用字体与设备实测锁定。正文换行、控件遮挡、缺失内容与错误状态按语义严格检查，不能靠像素平均分稀释。

每个差异包含元素、两端参数、截图、原因、影响和处理决定。字体栅格化单独比较字形边缘；整体布局、内容和操作差异仍逐项解决。
