# 01 需求与复刻规格

## 1. 范围与事实源

本项目的产品范围是固定基线下的全部手机 Web。产品行为由 Web 页面、调用代码、服务端契约与可复现操作共同确定。开发从这些来源提取规格，再在 Android 原生实现。

事实源顺序：明确的产品决定 → 固定基线的实际行为及服务端规则 → 源码和测试定义 → 本方案的实施建议。发现矛盾时建立差异记录，核对复现条件后决定；不得只凭组件名称推断行为。

固定基线见 [baseline.json](baseline.json)。真实服务器当前版本尚未读取，P0 需使对照服务器与基线一致，或登记一次明确的基线更新。整个开发周期使用同一份基线记录。

## 3. 导航和信息架构

手机壳采用一个共享顶栏、左导航抽屉、右项目 / 控制台抽屉。写作和游戏在导航中为两个并排入口。默认工具顺序为工作台、资料库、创作方案、版本管理、书籍管理、Skills、Agents、自动化、资源中心；设置位于末尾。开发模式的 trajectory 位于工作台之后。动态插件默认插入 story 之后，在手机归入工具组；用户已保存的排序优先。

手机导航从 `allActivityItems` 构造，不筛选 `hiddenActivityIDs`；桌面隐藏的入口在手机仍显示。验收需包含保存隐藏设置后进入手机布局的场景，手机不增加基线未提供的隐藏功能。来源：[默认顺序](https://github.com/SeraphHsing/denova/blob/671ef4eb609523f07d1c234cdcd242d63ce12652/web/src/components/workbench/workbench-activity-order.ts#L17)、[手机可见性](https://github.com/SeraphHsing/denova/blob/671ef4eb609523f07d1c234cdcd242d63ce12652/web/src/components/workbench/WorkbenchShell.tsx#L438)。

导航顶部包含书籍切换、命令搜索、消息入口和通知提示；设置拥有独立入口。点击目的地先关闭抽屉，再切换内容。任意时刻只有一个一级目的地高亮。菜单排序、自定义和条件入口按基线逐项核对。

写作的“正文 / Agent”分别保留状态；选择文件进入正文。当前路由负责顶栏控件，缓存的其他页面不得占用顶栏。项目目录和游戏控制台按当前页面提供右侧内容。

来源：[WorkbenchShell](https://github.com/SeraphHsing/denova/blob/671ef4eb609523f07d1c234cdcd242d63ce12652/web/src/components/workbench/WorkbenchShell.tsx#L189)、[手机布局](https://github.com/SeraphHsing/denova/blob/671ef4eb609523f07d1c234cdcd242d63ce12652/web/src/components/layout/workspace-mobile-layout.tsx#L45)、[写作分页](https://github.com/SeraphHsing/denova/blob/671ef4eb609523f07d1c234cdcd242d63ce12652/web/src/components/workbench/MobileWritingWorkspace.tsx#L13)。

## 4. 每个页面必须展开的状态

每个页面登记：未连接、鉴权中、首次加载、空数据、正常、局部加载、未保存、提交中、提交结果不明、已保存、校验失败、权限不足、并发冲突、请求失败、重连、恢复中及对应禁用状态。只登记该页面实际存在的状态，避免人为增加流程。

每个可写表单还需登记初始值来源、必填与可清空字段、层级覆盖、校验时机、确认动作、提交期间可否返回、失败时输入保留、成功后的缓存失效与选中项变化。

每个列表登记分页 / 增量加载、排序、搜索、整行展开、选择、批量操作、长标题、空结果、失效条目与返回后的滚动恢复。

## 5. 操作契约格式

实现任何操作前填写一条行为记录：

```text
ID / 基线提交 / 页面及控件
初始条件：服务器、权限、项目、会话或分支、revision、任务状态
步骤：点击 / 输入 / 选择 / 滑动 / 返回
界面结果：文本、焦点、滚动、浮层、可用状态
请求：method、path、query、body、Cookie、命令与操作身份
服务端结果：变更的记录、文件、会话、队列或任务
失败结果：输入保留、错误、可恢复入口、是否允许重试
证据：Web 与 Android 截图 / 录屏、脱敏请求、重新读取的结果
```

“按钮可点”“请求返回 200”“APK 可安装”各自只能证明对应步骤，完整操作以最后一次重新读取或最终状态为准。

## 6. 输入、焦点、返回和手势

游戏输入框中 Enter 换行，点击发送才提交；行动选项先填入输入区。其他输入组件以各自 Web 行为为准。中文 IME 组合态未提交时，不得因 Enter 或重组触发发送、保存或重复字符。

打开抽屉时焦点移到抽屉返回控件，关闭后返回有效来源控件。返回只处理当前最上层的操作：IME / 选择态、菜单、对话框、抽屉、页面内部返回，再到系统离开；具体优先次序需在相同组合场景对照 Web，并完成 Android 系统返回适配。

边缘打开、抽屉标题栏关闭、垂直阅读与编辑区的手势互斥遵循 [04 界面规范](04-ui-and-editor.md)。Android 系统返回保留系统含义，App 按钮提供抽屉入口；系统手势占用区域的差异登记为平台差异。

## 7. 远程权限和动态扩展

`authenticated` 和 `local` 是两个独立事实。手机 App 的访问身份由服务器判定。局域网地址不使客户端成为服务器本机。

扩展管理的读取及部分配置写入在远程可用；本机限定操作按相同规则禁用并显示 `LOCAL_HOST_ONLY` 对应文案。动态页面仍应出现在相同条件下，进入后呈现 Web 的可用信息、配置或受限状态。

插件运行界面使用 loopback runtime / iframe。纯原生 Android 没有据此获得通用的插件 UI 渲染契约。本项目只承诺固定手机远程 Web 基线下实际可用的表现；若实测有远程可用的任意 HTML 运行页面，登记原生路线的能力缺口并在该模块开工前作出明确产品决定。

管理端例外规则见 [platform/api.ts](https://github.com/SeraphHsing/denova/blob/671ef4eb609523f07d1c234cdcd242d63ce12652/web/src/features/platform/api.ts#L148)。

## 8. 全量完成标准

复刻矩阵中的每一行必须有实现位置、验证环境、双端证据及结论。条件入口在相同触发条件下测试；远程受限项用“限制行为一致”通过，不能直接跳过。

页面覆盖率与流程覆盖率分别统计。每个功能族的成功、失败、权限和恢复路径均需纳入；不能用简单页面数量代表功能完整度。P0 结束时冻结本次矩阵范围，新增基线行为经范围变更登记后进入。

最终通过要求：范围内无未实现项、无未解释差异、无阻断流程问题；保存、审批、任务归属和恢复用例全部通过。平台差异保留经过确认的记录。发布报告必须明确真实验证的设备、服务端版本和剩余限制。
